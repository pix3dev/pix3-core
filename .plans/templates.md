# Templates: two blank starters (P1)

Date: 2026-10-10. Owner decision of that day, overriding `../pix3/.plans/pix3-core.md` §G.2 row
«`create-pix3` + 4 рецепта» and §A.1 «шаблоны … и kit, код бандлится внутрь»; the shape of a
project is §B.5 «Шаблон», which stays authoritative. Where this file disagrees with the plan it
says so (AGENTS.md rule 13).

`CP` = `packages/create-pix3`, `CLI` = `packages/cli/src`, `RT` = `packages/runtime`.

## Decisions

| # | Decision | Why |
|---|---|---|
| T1 | **`npm create pix3` ships only blank starters: `2d` and `3d`.** Every template with game mechanics (`recipe-{tapper,bouncer,arena,blank}-2d`, `recipe-grid-3d`, `minigame-2d`, `playable-2d/3d`, `idea-blank`, the 1.x `empty-2d/3d` with logo and demo box), the recipe catalog (`CP/src/recipes.ts`) and its specs (`recipes.spec.ts`, `recipe-game-rules.spec.ts`, `playable-3d-bookkeeping.spec.ts`, `recipe-bouncer-2d/ball-collision.spec.ts`) are removed. | Owner: the coding agent builds the game; a recipe it has to unlearn costs more than an empty scene. A recipe also binds the kit to its node ids, signals and `design/recipe.md`. |
| T2 | **Composition, not two trees.** `CP/templates/base/files/` is everything both starters share; `CP/templates/{2d,3d}/template.yaml` says `extends: base` and the layer's `files/` adds one scene. `CLI/templates.ts` reads `extends` into `layerDirs`; `CLI/new-project.ts` copies the layers, then the template's own files on top (same path → the template wins). A folder without `template.yaml` is a layer and is never listed. | One `package.json` / `vite.config.ts` / `tsconfig.json` to keep current. |
| T3 | **The base layer is §B.5:** `package.json` (deps `@pix3/runtime`, `three ~0.183`, `postprocessing`, `lit`; dev `vite ^8`, `@pix3/vite-plugin`, `@pix3/cli`, `typescript`; scripts `dev`, `build`, `preview`, `check`, `smoke`), `vite.config.ts` with `pix3()`, `index.html` (`#app`), `src/main.ts` (`startGame('#app')` from `@pix3/vite-plugin/player`), `tsconfig.json` (bundler resolution, `vite/client`, strict), `gitignore`, `README.md`. Flat `design/ scenes/ sprites/ scripts/ audio/` are created empty. **Two additions to §B.5's list:** dev `@pix3/editor-core` — the plugin finds the prebuilt editor in the project's own `node_modules` (`findPackageDir`), nothing else depends on it, so without it `/__pix3/` has no editor; dev `@types/three` — the runtime ships TS sources that import `three`, so `pix3 check` (the project's own `tsconfig.json`) needs its types. | §B.5, plus what a fresh project needs to run `npm run dev` / `npm run build` / `npm run check` out of the box (measured below). |
| T4 | **The layers:** `2d` — `scenes/main.pix3scene` = `Group2D` `game-root` stretched over `viewportBaseSize` + a `ColorRect2D` background; `3d` — `Node3D` `game-root` with `Camera3D`, `DirectionalLightNode`, `AmbientLightNode`. No component anywhere (the spec asserts it). Both 1920×1080, `targetPlatform: universal`, `entryScene: scenes/main.pix3scene` → `defaultExportScenePath`. The 2D runtime needs no camera node (the 2D pass owns its orthographic camera). | «one empty entry scene; nothing that plays». |
| T5 | Placeholders: `{{PROJECT_NAME}}`, `{{PACKAGE_NAME}}` (npm-safe slug, `packageNameOf`), `{{PIX3_VERSION}}` (the CLI's version = the lockstep `@pix3/*` version; the version gate wants them equal). `.html` is text now. `gitignore` is shipped under that name and written as `.gitignore`: npm drops `.gitignore` from tarballs, and the templates travel in two (`create-pix3`, the CLI's `templates/` copy). The template's `.gitignore` already lists `.pix3/`, so the kit does not append a second line. | |
| T6 | **`create-pix3` is a thin bin over `pix3 new`**, not a bundle of the CLI: `CP/index.js` → `CP/src/create.js` parses `[dir] [--template 2d\|3d] [--name] [--yes]`, asks 2D/3D and the folder in a terminal (`--yes` or no TTY: `2d`, `pix3-game`), and spawns `pix3 new <2d\|3d> <dir>` of the `@pix3/cli` it depends on (its `src/index.ts` in a checkout, the published bin otherwise). Plain JS with `checkJs`: a create-* bin runs from `node_modules`, where Node does not strip TypeScript, so a TS bin would need a build. Engines follow `@pix3/cli` (`>=24.15 <25`). **Deviation from §A.1** («код бандлится внутрь»): one implementation of project creation (templates, manifest, kit) instead of two; `@pix3/cli` has no hard dependencies, so the extra install is the CLI itself, which the starter installs anyway. | |
| T7 | **The corpus moved, it was not dropped.** The specs that ran over every template scene — saver fixed point (`RT/src/core/scene-saver-stability.spec.ts`), `ScenePatchWriter`/merge (`editor-core/src/core/scene-patch/scene-patch.spec.ts`), loader golden (`RT/src/core/scene-loader-node-profile.spec.ts`), `pix3 validate` / `pix3 smoke` goldens, `pix3 check` / `tree` / `kit` specs, the routine-format spec — now run over the starters **plus** `RT/fixtures/scene-corpus/` (`git mv`'d with history): `recipe-tapper-2d`, `recipe-bouncer-2d`, `recipe-grid-3d`, `playable-3d`, `minigame-2d` in the template layout (`template.yaml` + `files/`), so `createProject` instantiates them for the CLI specs. Kept: scenes, scripts (the loader golden registers `user:*`), the sprites the scenes reference, the three routines the format spec reads. Dropped: covers, READMEs, `design/recipe.md`, `reachability.json`. With the starters they cover every node type and `core:` behaviour the eleven templates used (`HemisphereLightNode`, `PostProcess`, `Checkbox2D`, `GeometryMesh`, `core:Hitbox2D`, `core:Sine`, `core:Rotate`, `core:tint`, prefabs, `scenes/ui/` overlays …); the one variant gone is a `standard`-material `GeometryMesh` (the old `empty-3d`'s box; `lambert` stays in `playable-3d`). 19 scenes instead of 30: the eleven gone were near-duplicates (arena ≈ tapper, blank ≈ tapper/bouncer, playable-2d ≈ playable-3d, idea-blank ≈ an empty 2D root). `scene-corpus.ts` exports `TEMPLATES_ROOT` and `CORPUS_ROOT`; `npm run test:corpus` unchanged. | Owner: keep a meaningful corpus, as minimal per-package fixtures. |
| T8 | The kit prose lost its recipe guidance (`design/recipe.md` reading order, the «Recipe tool names» table, «extend a recipe's scripts», recipe-specific examples in the skills); `AGENTS.md` describes the empty starter and the Vite entry files. | The files it pointed at no longer exist in a new project. |

## Verification (2026-10-10)

- `npm test` (289 files, 3 403 tests), `npm run lint`, `npm run type-check` clean; `npm run test:corpus` (+ `../DeepCore`) 197/197.

- `../pix3-core-spikes/build-check/run.mjs` (now builds a starter made by the checkout's create-pix3; default `--template 2d`): 12/12 for `2d` and `3d` — `vite preview`, `file://`, sandboxed iframe all `running`, frames counting, no errors.
- Headless Chrome on `npm run dev` of each starter: `/__pix3/` mounts (`__PIX3_DEBUG__.status().activeScene = res://scenes/main.pix3scene`, writer `self`, nothing dirty, scene tree `Game Root` + children, no page exception, no console error; the Run menu is Play Game / Play Scene / Stop / Restart / Pause — no build), `/` runs (`__PIX3_PLAYER__.status = running`, no errors).
