## Debt

- Frames must be PNG (`character-compile` reads the IHDR itself). WebP/JPEG frames would need the runtime's `image-header-size.ts` exported to the CLI's Node code, or a copy — not done.
- `pix3 kit --update` (without `--migrate`) still leaves files a newer kit stopped shipping; only `--migrate` removes them. Fold the retired-file step into `--update` when the 2.x kit first drops a file.
- The migrate report cannot tell an edited 1.x kit file from an unedited one when `.pix3/kit-manifest.json` is gone (a fresh clone: `.pix3/` is gitignored) — every file then counts as edited and is kept (with the 1.x ones flagged and staged). The 1.x kit's own hashes per release are not recorded anywhere to fall back on.
- `validate` and `tree --props` are not version-gated (the plan names `check`/`smoke` only); a `validate` against a 1.x runtime project still answers about the 2.x engine.
- `pix3_scene {nodeId}` answered `properties.label: "Play"` right after an inspector commit of `Coins 🪙` (before a sync) while the file got the new value — the bridge's `properties` look like the loaded document, not the live node. Not investigated (bridge, not this work); noted for `.plans/agent-bridge.md`.
- `pix3 <command> --help` prints the top-level usage for every command (the entry handles `--help` before dispatch) — `character-compile` has a full `CHARACTER_COMPILE_USAGE` that only `pix3 character-compile` with no spec reaches. Pre-existing for all commands.
