## 0. Decisions

| # | Decision | Why |
|---|---|---|
| W1 | **`norm` in the editor is editor-mode on all three sides.** `baseline.norm := normOf(graph)` of the graph parsed from exactly the baseline text, right after the parse (before any operation); the external version E is parsed by the same `SceneManager` loader (textures come from its cache) and `normOf`'d. Disagrees with §C.2 "натуральный размер … из заголовка картинки … в редакторе" — that is S12 §4.2 option (a); this is option (b). | `SceneLoader` awaits every texture during the parse, so a fresh graph already carries the decoded natural size. One loader on every side cannot disagree with itself; a header parser in the editor could (SVG without `width`/`height`, where the browser's size is not in the header). |
| W2 | The image-header size reader lives in `RT/core/image-header-size.ts` (PNG, JPEG, WebP, GIF, SVG attrs/viewBox) and `NodeAssetLoader` uses it, so `pix3 validate`/`tree`/the plugin see the same `Sprite2D` size the editor does (spec: an un-sized `Sprite2D` normalises to the PNG's size in Node). Cross-checked in Chrome against the decoded size for every textured node type (`size-crosscheck.mjs`, 39 checks). | §C.2 "в редакторе, CLI и плагине одинаково" — the CLI side is where a header is the only source. |
| W3 | Baseline is `{path, sha, text, norm}`; no cached AST. The writer parses the text once per flush. Disagrees with §C.2 `{sha,text,ast,norm}`. | A cached `yaml` AST is mutable shared state; the parse is the cheap part (S12: 21 ms on the largest file). |
| W4 | Pure code (`diff`, `ScenePatchWriter`, `merge`) in `EC/core/scene-patch/`; services in `EC/services/project/`: `SceneBaselineService` (replaces `SceneDiskStateService`), `FlushService` (replaces `SceneWriteService` internals, keeps its public methods so mount/bridge/shell do not change), `SceneDraftService` (IndexedDB). | AGENTS.md: services by domain; non-services in `core/`. |
| W5 | Saver fixes in `RT/core/SceneSaver.ts` + `RT/nodes/Node2D.ts`: (1) a fixed property order — the keys of the node's bag in their order, then keys a type branch materialises, `transform` last (some nodes, lights, build their bag in the constructor, so "the file's order" is not available for every key) — `save(load(save(x))) == save(x)`; (2) `layout:`/`flow:` blocks carry `enabled` plus non-default keys only, and a disabled block with non-default keys is kept as `enabled: false` (closes S12 §4.4 "flow params lost while disabled"). Layout-derived values: see W16. | §C.2 "Исправления saver'а"; S12 §2.3, §4.1, §4.4. |
| W6 | Fallback when the writer refuses (aliases, non-empty flow `children`, a `PatchError`): full serialization via the fixed saver, with a warning in the log. | §C.2. |
| W7 | `ExternalChangeService` keeps stabilisation + play hold + parse check; it reports into one consumer, `ExternalReloadService`, whose dirty branch becomes the §C.3 key-level merge (`SceneMergeService`). Known-hash recognition moves to the baseline. | One path for external versions (task brief). |
| W8 | Plugin: `.pix3/tx/` changeset (`POST /__pix3/api/changeset`), `.pix3/history/` journal (`GET /__pix3/api/history`, `POST /__pix3/api/history/restore`), recovery at start, claim and every write under the existing `serial` mutex. Single-file `PUT` stays for non-scene writes. | §C.4; port plan D6 / §8.10. |
| W9 | Notices ("тост" of §C.1/§C.3) are `appState.project.host.notices` owned by `HostNoticeService`, rendered under the state banner of `pix3-host-banner`, each also written to the log. | No toast surface existed; the banner is where "this tab cannot save" already lives. |
| W10 | `EditorHost` gains optional `history` (journal) and `files.writeChangeset`; `HostFileFailure.path`. A host without them degrades: no journal (merges still work, "kept in History" is not promised), per-file writes. | The contract is the seam (port plan D1). |
| W11 | Esc during a drag cancels it (nodes back, no operation): 2D handle drags and the 3D gizmo (`cancel3DTransform` ends the `TransformControls` drag with its `mouseUp` ignored). | Gate row "Esc во время drag" assumed an affordance the editor did not have (rule 13). |
| W12 | A read-only tab follows the writer tab: `ExternalChangeService` skips only frames whose `writerId` is this tab's (it skipped every `author: 'editor'` frame), and `scene.reload` / `scene.refresh-prefab-instances` are allowed in read-only mode. | Found by the browser gate: tab B kept a stale scene. |
| W14 | A scene file that is exactly what `JSON.stringify` prints (minified or indented) is patched as data and re-printed with its own layout (`scene-json-writer.ts`); anything else takes the YAML splice path. | DeepCore has JSON scenes (valid YAML); the splice writer produced invalid YAML on them and every flush fell back to a block-YAML rewrite. |
| W15 | An SVG's header size is what Chrome's `<img>` decodes: a missing/relative width or height comes from the `viewBox` ratio, else 300×150. | Measured in the browser (`size-crosscheck.mjs`, 13/13); a `viewBox`-only SVG is 300×150 there, not its box. |
| W16 | **Flow-computed values are masked, not written.** `editorNormOfGraph(graph, B)` (= `normOfGraph` with every flow-derived leaf set back to B's value: a flow child's position — main axis only for an anchored child —, an `autoSize` container's main-axis size, the same as prefab-instance overrides) is the G of every diff: flush, draft, merge, bridge. `normOfGraph` stays for a fresh parse (a baseline, E). Anchor-layout rects (stretch/edges after a parent resize) are **still written**; a merge that drops the parent's resize drops them with it (`laid-out`). | Closes S12 §4.1(б) for the flow, contained in the editor (`EC/core/scene-patch/layout-derived.ts`). The anchor rects are not derivable: a child's rect against its parent's authored size is how the margins are stored (`Node2D.resolveHorizontalLayout`), so omitting it would move the child on reload. |
| W17 | Clobber detection keeps a **flush ledger** per path (key → value written, values replaced) since the last external version; E putting any key back to a replaced value is "agent overwrote your edit" for all of them; E settles the ledger. Replaces `LastFlush`. | §C.3 accepted "only the last flush" as a regression vs 1.x; the ledger is the protected set's window without its persistence. |
| W18 | **A write without an answer may have landed.** A flush failing with no HTTP answer records the sha of the text it sent (each attempt on the same baseline); a disk with exactly those bytes is the editor's own write — a 412 naming it or `ExternalChangeService` seeing it adopts it as the baseline (`acceptOwnHash`), and a draft stores those shas (`unconfirmedShas`) and is offered over either. | The N9 flake: Vite destroys open sockets on `close()` after the plugin renamed the file in place. A sha match is proof the bytes are this text, whoever answered. |
| W19 | **A changed script re-derives the baseline norm**, like a changed prefab (W-M5): when `LiveComponentService` replaces live components of a re-registered script (`.plans/scripts-vite.md` S7), B.norm is rebuilt from B.text with the new classes (B.text and B.sha unchanged) and the new instance's config is that load's plus the unsaved keys. | A default the new class adds is in every fresh load of the file, so it must be in B too, or the next flush writes it as an edit; the dirty scene's own keys stay pending. `df50626`; gate P1 rerun 37/37. |
| W20 | **Locale tables (`locales/<id>.json`) follow the disk under the same discipline, cut to their shape.** `LocalizationEditorService` keeps a baseline per table (`{sha, table}` of the last disk version it read, followed or wrote — not `SceneBaselineService`, whose baseline carries a scene norm; a table is its own norm). Edits still write through on commit (one key per commit, no gestures, so no idle/cap timing), one at a time, `If-Match` = baseline (`createOnly` when the file was absent or unreadable at load, so a broken file is never written over). A refused write and an external version (`ExternalChangeService` → `ExternalReloadService`, which hands `locales/*.json` to the service; a delete/rename straight from the `pix3:fs` frame, which the settling path does not deliver) go through the key-level merge `EC/core/locale-table-merge.ts`: per key, L = B → E; E = B → L (the edit is written on top of E); both changed differently → E stays, a notice names the keys (`HostNoticeService`), the editor table goes to the journal as `rejected-draft` (`SceneJournalService`; the plugin now journals `locales/*.json`, `isJournaledPath`). The flush ledger (W17) per table: an external version that puts back a value the editor's write replaced → "An agent overwrote your edit [Restore my edit]". A file that does not parse keeps the last good table (and its unwritten edits). New/deleted files add/remove the table (only declared locales when `pix3project.yaml` lists them; a deleted declared one is an empty table). The panel: a cell being typed in (not committed) survives a re-render for another key; if the disk changes that same key, the cell shows the disk value and a notice says the text was not saved. The sync's flush (step 0) writes a table whose write failed without an answer. | The brief: an agent's new/changed table appeared only after a reload, and a panel edit saved the whole table on a stale read (the `knownHashes` If-Match was whatever was read last, a 412 was only logged and the edit was gone from disk). Not reused, on purpose: `FlushService` timing and `SceneDraftService` (a commit is on disk within one request; a write that fails without an answer is retried by the next edit or sync, but does not survive closing the tab — debt). |
| W21 | **Anchor margins live in the `layout:` block** (owner decision 2026-10-10: little legacy, format change OK). `layout: {enabled, horizontalAlign, verticalAlign, left?, right?, top?, bottom?}` — the sides the alignment keeps (`left`→`left`, `right`→`right`, `stretch`→both; same vertically), the distance from the parent's edge to the node's. `Node2D` stores them (`resolveLayoutMargins`, `isMarginAxis`, `usesLayoutMargin`); the layout resolves an anchored axis from them against the parent's *current* size; the saver writes nothing they derive (`SceneSaver.dropMarginDerivedRect`: `0` for the `position` component of an anchored axis — a vector cannot lose one component —, no `width`/`height` under `stretch`; the same on the instance diff, both base and current masked). **Legacy files** (no margins) derive them once from the authored rect against the parent's authored size, in the saver (pure, for the baseline norm) and in the first layout pass (stored under a 2D parent) — the same numbers, so nothing is pending on open. **A root keeps its rect**: its reference is `viewportBaseSize`, which the file does not know; a hand-written root margin is honoured. A parent flow's main axis has no margin. Instance roots carry `layoutLeft` … `layoutBottom` (schema names, placement, `isInstancePlacementProperty`), applied by the loader after the aligns whatever the key order. **The first write of a legacy scene converts it** (`EC/core/scene-patch/legacy-anchor-conversion.ts`, in `FlushService.snapshot` and the merge's write of E): leaf ops that add the missing margins, zero the anchored position components and drop the stretched sizes of every anchored node whose text entry lacks a margin the norm has — a partial patch is not sound (a parent's new `width` re-means every child rect in the file; a `0` placeholder needs its margin). Editor intent: a drag / inspector rect edit re-derives the node's margins (`captureAuthoredLayoutRectFromCurrent(true)`), a reflow after a parent resize leaves them; an alignment change prunes the sides it no longer keeps so a stale one cannot move the node later. The inspector shows a number row per margin the anchors keep, under the modes. W16's `laid-out` merge reason is gone (nothing of a child's is pending after a parent resize). No scene-format version bump, no migration command: the loader and `pix3 validate` read both forms; DeepCore converts file by file as the editor saves them (not touched here). Also: `Sprite2D.setTexture` fills only the axis the file leaves out (it replaced both), the runner lays 2D roots out before the pre-roll tick (`onStart` reads resolved rects). | The debt below: a container resize wrote every anchored child's rect, and a merge had to drop them with a dropped resize. Proof: the HEAD-vs-new golden over the corpus and DeepCore (31 scenes, 554 `Node2D` rects × design/1.5× wide/1.4× tall: identical from the legacy text and from the re-saved text), now the committed spec in `scene-saver-stability.spec.ts`; `Node2DLayout.spec` (format, fixed point, a parent resize = one line, drag vs reflow, inspector margin, root, flow axis), `legacy-anchor-conversion.spec`, `layout-derived.spec` (the resize pending = the parent's width only; a moved child is its margin, kept through a dropped resize). |
| W22 | **A locale table's write that got no answer is drafted** (closes the W20 debt). `SceneDraftService` gains file drafts over the same IndexedDB store (`putFileDraft` / `getFileDraft` / `dropFileDraft`, keyed `<projectId>\0locales/<id>.json`, `revision: 0`): `LocalizationEditorService.writeLocale` checkpoints the text it meant to write against the baseline sha it wrote on (`''` for a declared locale whose file does not exist yet — a `createOnly` write) when the write fails without a conflict, and drops it when a write lands (the next edit's, the sync's step 0, "Restore my edit"). On the next open of the project, `loadTables` offers each declared locale's draft the way N9 does: dropped silently if the disk already has that table, offered (`Unsaved edits to locales/en.json … [Restore] [Discard]`) if the disk sha is the draft's baseline, else `rejected-draft` into the journal with a warn notice. Restore replaces the editor's table and writes it (`If-Match` on the baseline). | The debt: "an edit whose write failed without an answer is kept in memory only (no IndexedDB draft; lost if the tab closes)". Not a 2 s checkpoint loop like the scenes': a locale write is one request per commit, so the only state that can be lost is a failed write's — drafted at once. Specs `LocalizationEditorService.spec` (W22 block: checkpoint → reopen → Restore writes; older disk → journal; a landed write drops it; a declared file-less locale drafts against `''`); browser `../pix3-core-spikes/editor-e2e/locale-draft.mjs`. |
| W23 | **A square under `stretch` is the margins' too** (closes W21's `size`/`radius` debt; owner decision 2026-10-10, "small runtime/editor debt, if contained" — it is: no format change, one runtime rule, one key list). A node whose rect is one key for both axes (`Checkbox2D` `size`, `Joystick2D` `radius`) takes its side from the stretched span: one axis stretched → that span, placed on the other axis with that side (`Node2D.applyAnchoredLayout`, `resolveAxisLayout(…, placedSize)`); both → `Checkbox2D` the larger span, `Joystick2D` the smaller (the existing `applyCurrentLayoutSize` reduction). So the key is derived as soon as one axis is a stretched margin axis, and the saver leaves it out like `width` under `stretch` (`Node2D.marginDerivedSizeKeys` feeds `SceneSaver.dropMarginDerivedRect` and the instance-diff mask); the first-write conversion deletes a legacy `size`/`radius` with the stretched `width`/`height`. An inspector `size`/`radius` edit re-derives the margins (`captureAuthoredLayoutRectFromCurrent(true)`, as for `width`), so it writes the stretched axis's margins and the reload has the new side. Not a format change: the loader and `pix3 validate` read both forms; a legacy file's `size` still derives the margins (the authored rect), a margin-form file does not need it. A non-stretched square writes its key as before; a root keeps its rect (no margins, key written). | Before, a square's side under single-axis stretch was `max` (`Checkbox2D`) / `min` (`Joystick2D`) of the span and its *own* previous side, which the editor re-captures after every parent resize: neither derivable from the margins nor stable — the key was written on every parent resize, a `Checkbox2D` widened once never shrank back (400→500→400 wide: side 40→140→**140**), a `Joystick2D` under vertical stretch never grew (300→400 tall: radius 30→**30**), and the non-stretched axis was placed with the stale side (the 140 box hung 50 px over the panel's top margin). Dropping the key without the rule would have been unsound (a reload would place the square with the default side). Proof: `Node2DLayout.spec` "a square node under stretch" (legacy file → margins, no key, fixed point; parent resize = the parent's lines only, fresh load = same squares, back to the start = the original file byte for byte; inspector `size` edit → margins, reload keeps it; non-stretched square keeps its key) and `layout-derived.spec` "W21 for a square" (pending after a resize = the panel's `width`/`height` only; the first flush converts the legacy squares — no `size:`/`radius:` line, `norm(written) == G`, same squares on reload, the next resize writes one line; inspector edit = the three margins of the box). Six of the eight fail on `main` (the runtime fixed-point and inspector-edit cases pass there too: they hold under either rule). |
| W13 | `__PIX3_DEBUG__.status()` reports `dirty`, `flushing`, `gestureInProgress`, `pendingExternal`; `node(id).saved` is the node as the file gets it, `pending()` the unsaved keys per scene, `screen(id)` a node's origin on the page (to click or drag it). | The agent's view of §C.1's "dirty" indicator and of why a sync answers `gesture_in_progress`. |
